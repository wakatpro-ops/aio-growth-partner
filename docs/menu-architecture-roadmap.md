# AIO boost メニュー構成と段階的ロードマップ

更新日: 2026-09-03
管理Issue: #119

## 決定した完成形

店舗側の主要業務メニューは次の6領域とする。

1. 店舗トップ — 業種別の経営司令塔と今日やること
2. AIO改善 — AIから見つけられ、おすすめされやすくする情報整備
3. 売上・経理 — 売上、見積、請求、入金、経費、伝票、会計出力
4. 顧客 — 顧客台帳、セグメント、再来店支援、メッセージ下書き
5. 集客・販促 — AI提案、投稿、口コミ、配信予定、効果確認
6. 業種別の商品・在庫 — メニュー、商品、材料、仕入、棚卸を業種の言葉で表示

`設定` は主要業務とは分けた補助領域に置く。`データ取り込み` は独立した主要メニューにせず、関連する各ハブと設定から開く。

## 今回実装する範囲

- サイドバーを6つの業務入口へ再編する
- 店舗切り替え時も同じ業務ハブを維持する
- 業種に合わせて商品・在庫の名称を変える
- 売上ハブに経費、OCR伝票、会計出力、freee確認への導線を統合する
- 顧客ページを顧客台帳、分類、案内文、一括取込のハブにする
- 集客ページを提案、下書き、口コミ、予定、成果、チャネル確認のハブにする
- 商品・在庫ページに商品一覧、仕入、OCR、データ取込を統合する
- 設定からAIデータ取り込みを開けるようにする

## 準備が整ったら提案・実装する項目

### 予約管理

後回し理由: 現在は初期設定で運用方法を確認できるだけで、予約の作成・変更・キャンセル、スタッフ・設備枠、通知、権限テストが揃っていない。これらが完成し、実店舗テストを通過した段階でメニュー名を `顧客・予約` へ変更する。

### 銀行・カードの直接同期

後回し理由: 接続先選定、契約、本人同意、トークン保管、取消・重複取込の仕様が必要。まず請求・入金記録とCSV取込を正本として運用を確認する。

### 簡易レジ

後回し理由: 既存POSと衝突しない対象店舗、税・取消・返金・締め処理、在庫・会計連動の要件確定が必要。現在は利用中の仕組みを置き換える表示をしない。

### 天気連動・需要予測・利益予測・離反予測

後回し理由: 十分な期間の実データと、予測精度を評価するKPIが必要。根拠のない予測値は表示しない。先に実績値、在庫アラート、確認可能なルールベース提案を整える。

### Google・Meta・LINEの自動取得・自動公開

後回し理由: 各審査、権限、利用枠、オプトインが必要。審査完了前は下書き・確認・手動反映を維持し、利用可能と誤認させない。

### 全画面固定AIチャット・全入力のモーダル化

後回し理由: 画面を狭くし、作業中の文脈や入力内容を失う危険がある。AI相談はサイドバーから任意で開き、複雑な業務は専用ページで完了させる。

## 再提案する条件

上記の後回し項目は、外部審査の承認、必要契約の締結、データ量の充足、または各機能の作成・編集・削除・権限・監査・実店舗テストが完了した時点で、Issue #119とこの文書を起点に再提案する。
