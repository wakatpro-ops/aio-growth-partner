# 写真で使う商品・在庫ワークベンチ

2026-09-24 / 承認済みUI提案の実装仕様

追跡: https://github.com/wakatpro-ops/aio-growth-partner/issues/152

## 既存との差分

既存の商品写真・商品編集・在庫履歴・伝票OCR・売上明細を再利用する。
横に長い在庫表と一括入力フォームを入口にせず、業種別の3タブと写真カードを入口にする。

## 今回の受入条件

- メニュー / 食材・仕入 / 売れ方・利益（他業種は適した名称）。スマートフォンで横スクロールせず操作可能。
- 写真なしでも利用可能。名前・価格の税込/税抜・販売中/売り切れ/お休みをカードに表示。
- 担当スタッフは状態・入荷・廃棄を操作。価格・原価・仕入下書き・分析はオーナー/店長/運営管理者のみ。URLとServer Actionでも検証。
- 売り切れは削除と区別する。過去の取引と商品を消さない。状態は戻せる。
- 入荷は数量と単位を人が確認して確定。発注書の作成だけでは在庫を増やさない。
- 伝票OCRの結果を入荷下書きへ引継ぎ、商品・実際の入荷数量・単位を確認。単位変換を推測しない。同一伝票の二重入荷を防ぐ。
- 仕入は送信前の文書下書き。取引先・商品・数量・単価・金額を確認して印刷可能。外部へ送信したと表示しない。
- 下書きは編集/削除（アーカイブ）/復元可能。確定した入荷は履歴を保持し、取消は逆仕訳で残す。
- 売れ方は期間付き実売上明細だけ。数量ランキングと現在の登録価格・原価による参考利益を区別。未紐付け・原価未設定は説明し、架空の利益率や欠品日数を作らない。
- AI提案は既存の小さなチャット入口へ文脈を引継ぐ。大きなロボット列は増やさない。
- 保存の即時フィードバック、サーバー側冪等性、他店舗・所属なし・閲覧者・停止アカウントの拒否を検証。

## 外部条件が揃うまで行わないこと

仕入先への自動発注、外部POSの価格自動変更、レシピ未登録の原価計算、使用量不明の欠品日予測。
今回の保存先はAIO boost内。仕入書は未送信と明記する。

## 検証と公開

純粋関数テスト、型検査・Lint・build、専用ステージングでDB RPC拒否/ロール/重複/取消の検証、PC/モバイル画面確認後にPR・マージ・本番反映する。
