# 運営者専用 AI利用料と稼働状況

Issue #170。入口は `/admin/ai-logs`。店舗オーナー・店長・スタッフには公開しない。
モデル、プロンプト、回答長、再試行設定、利用上限は本変更では変更しない。

## 計測と表示

- 月の境界は日本時間。API HTTP試行ごとに記録し、同じ業務処理の2回目以降を再試行として数える。SDK内部再試行とアプリのモデルfallbackも含む。
- Chat Completions / Responses の応答usageを利用する。計測・集計自体にはAIを呼び出さない。
- 対象は共通AI生成、店舗AI相談、店舗メール分類、伝票読取、SNS画像解析、申込解析、公開URL解析、外部AIでの見つかり方の8経路。共通生成はテンプレートごとの機能名で分ける。
- 入力合計はキャッシュ読取・書込を含む。費用は通常入力・キャッシュ読取・キャッシュ書込を排他的に算定し、出力の内数である推論トークンを重ねて加算しない。
- API実行時点の公表単価・料金版・返却モデル・使用量を保存。後から料金が変わっても過去費用は再計算しない。
- 費用は税抜USDの推計であり、OpenAIの請求確定額ではない。実際に実行されたWeb検索ツール料金を含む。未知モデル・tier・キャッシュ内訳・不明なツール費用は未算定として残す。
- 公開申込など店舗が未確定の費用も「店舗未割当・申込前」に含め、全体から落とさない。
- プロンプト・AI回答・メール本文・例外本文・APIキーは新しい利用証跡に保存しない。

## 月末見込みと急増

- 計測開始前の履歴は補完しない。計測開始はmigration日時ではなく、計測版が稼働後に明示的に有効化する。
- 月末見込みは現在月のみ、完全に観測された日本時間の日が3日以上で算定。記録済み費用＋完全観測日の平均×残り日数。未算定費用がある場合は見込みを出さない。
- 月途中開始時の見込みは「計測開始後から月末まで」であり、開始前の費用は含まれない。
- 急増は直近24時間対その前24時間。48時間の観測が必要。現在10回以上かつ2倍以上。前期間0回は倍率でなく「新しい利用」と表示。
- 障害で記録保存が失敗してもAIの回答や既存再試行動作を壊さない。保存失敗は固定識別子 `ai_usage_record_failed` で警告する。プロセス停止・通信断などによる記録欠落はあり得るため、監査・請求照合の最終根拠はプロバイダー側の請求/使用量とする。

## 円換算とAI原価率

運営者が対象月の「USD/JPY参考レート」と「AIObサービス利用料売上（税抜円）」を設定する。
既存の店舗の売上・請求書・入金をAIObの利用料と混同しない。現状の契約テーブルには確定した月別利用料がないため、自動推測しない。
未入力・分母0・計測期間不足・未算定費用がある場合、原価率は未算定。参考レートは請求時の確定為替ではない。
設定変更は運営者認証後に監査ログと同一トランザクションで保存。空欄で解除できる。

## 権限と運用

新規3テーブルはRLS有効、anon/authenticatedの直接アクセス不可（運営者JWTでも不可）。
運営者のサーバー処理が有効/未停止アカウントを確認して集計する。設定RPCもactorの運営権限と停止状態を検証。
イベントはサービスロールから追記・読取のみ。月次集計はSQLで行い、APIの最大1000行による欠落を避ける。

適用順:

1. `supabase/migrations/202610040001_ai_usage_metering.sql` を対象DBへ追加適用。
2. ステージングで `supabase/tests/ai_usage_metering_authz.sql` を実行（合成行は全てROLLBACK）。
3. 本番データ・正式URLを変えない隔離Previewで実API・権限・画面検証。
4. 本番の通常Production設定で計測版を配備。
5. サービス用 `activate_ai_usage_metering(now())` を一度実行し、開始時刻を読戻す。既存値は上書きしない。

単価根拠（2026-10-04確認）:

- https://developers.openai.com/api/docs/pricing
- https://developers.openai.com/api/docs/guides/prompt-caching#monitor-cache-performance

ローカル検証: `npm run test:ai-usage`、`npm run lint`、`npx tsc --noEmit`、`npm run build`、`npm run check:secrets`。
実API検証は通常テストとは分離し、隔離URLを `AI_USAGE_TEST_URL` に指定して `npm run test:staging:ai-usage` を明示実行する。

## 受入検証（2026-10-04）

- ローカル40テストと全8経路の計測カバレッジ、lint、型検査、Production build、クライアント秘密値チェックを通過。
- staging実DBでRLS/RPC権限、1,000件超の集計、月跨ぎ再試行、48時間窓、停止管理者拒否、設定と監査の原子保存を確認。SQL合成データはROLLBACK。
- 隔離Previewで未認証・オーナー・店長・スタッフの画面拒否と、運営者のみの閲覧を確認。運営者JWTでの直接DB読取も拒否。
- 運営者の実フォームで保存・再読込・空欄解除を確認。未設定の将来テスト月のみ使用し、値は解除済み。当月設定は変更しない。
- 実AI呼び出しは1回。実応答 `gpt-6-luna`、入力1,832・出力23・キャッシュ読取0・書込1,829トークンを記録し、保存単価から推定USD 0.000240425と照合。
- 1440px/390pxで利用量の実表示とページ全体の横溢れがないことを確認。スクリーンショットは非公開の一時領域のみ。
- モバイルの管理者ナビが横スクロールの外へ隠れる既存問題を修正し、320px/390px/1280pxのローカル描画で全管理者リンクを確認。店舗用ナビの動作は変更しない。
- 合成店舗・法人・利用者は削除済み。実際に消費したstaging利用証跡のみ保持し、削除済み合成IDへの参照はNULL化。プロンプト・回答・秘密値は証跡に含めない。
- 初回ブラウザー検証は設定操作前後で中断し、AI呼び出し0回で後片付け済み。段階別診断を追加した再実行で上記全項目を通過。
