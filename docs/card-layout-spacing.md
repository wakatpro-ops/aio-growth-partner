# カード一覧の余白・上端の統一

## 原因と修正

通常の文書フローを対象にした `.card + .card` 等の `margin-top: 16px` が、Gridの2枚目以降にも適用されていた。`main .menu-photo-card { margin: 0 }` は詳細度が低く、後ろに定義されていても打ち消せなかった。

- `gap` で間隔を管理する共通・専用レイアウト26種類の直下に限り、カードとグリッドの `margin-top` を0にする。
- 親・子それぞれを `:is()` で指定し、既存の兄弟セレクターと同じ詳細度で上書きする。`!important` や商品固有の位置補正は使わない。
- カード内部の文章・ボタンの余白、通常の文書フローでの16px間隔、明示的なインライン余白は維持する。
- 折り畳み式「機能一覧」の内側にも共通 `stack` を使用し、AIO改善等で段間隔が二重になる問題を防ぐ。

## 回帰検証

`npm run test:card-layout` は、詳細度・通常フローの保持・機能一覧の共通スタック・TSXソースで確認できる既存のgapレイアウトの適用漏れを検査する。新しい専用レイアウトがカード/グリッドを含む場合、共通リセットに追加するか既存レイアウトクラスを再利用する。動的なclassName・コンポーネント越しの子要素は画面確認も必要。

ローカル限定の一時QAページで実際の `MenuCards` に合成商品8件を渡し、PCの横並び・複数段、390px/320pxの縦並びを確認した。各段の上端一致、メニュー間18px、共通グリッド間16px、stack間18px、通常フロー間16px、横はみ出しなしを測定した。一時ページは本番ビルド前に削除しており、業務データ/AI/外部サービスへ書き込んでいない。

関連するvisual-first検査も、旧「売上グラフ→右側KPI」ではなく現在の「上段共通KPI→売上/経理タブ」を検証するよう更新した。
