# Excel取込の過剰な確認の修正（2026-10-04）

## 原因と変更

- 日別横持ち帳票は構造が判定できた表にも一律で `layout_confirmation` を作っていた。既知構造の表は最終確認だけとし、列の重複・日付・金額・集計の矛盾は引き続き質問する。
- 支払先の列が存在しない経費台帳にも必須列を要求していた。存在しない列は推測せずNULLの未承認・会計送信不可の下書きに保存する。支払先列が存在するのに空欄なら従来どおり確認する。経費承認時の必須チェックは維持する。
- 経費の日付が帳票月と異なる場合、「すべて元の日付を使う」を1回の提案・明示承認にまとめる。年/月の置換は表ごとに分け、同じ年月を異なる帳票へ一括適用しない。最大100表/提案、元データ・表単位の承認履歴・CAS・原子的RPCを維持。
- 画面の件数・保存した質問・修正案の残件は共通のグループ化処理を使用。元ファイルの問題は表ごとに表示し、ファイル全体の拒否と混同しない。保留は利用者が明示選択する。
- parser version: `2026-10-review-v4`。旧版の解析を新方式で確定しない。元ファイル・過去の解析・実績は自動変更しない。

## 検証

- 元の私有ファイルをローカルで読み取りのみ再現。2,529行・46表を維持。旧画面80件の確認を15項目に整理。非公開ファイル/氏名/数値明細をリポジトリへ保存しない。
- 45件の一律レイアウト質問、35件の存在しない支払先列の質問を除去。35件の経費日付は1項目へ。4件の同表見出し不一致は1項目で箇所を列挙。
- 対象月の相違、存在しない日付、調整差額、集計式に含まれない内訳は未解決のまま維持。数字が合うように推測で修正しない。
- 合成データのパーサー、承認再生、35表の一括承認、同時更新、権限、保留/再開、再試行、証跡保持テスト。
- 既存ステージングの使い捨て架空店舗で実DB/RPC/RLS/取込の統合テスト。NULL支払先は `needs_review` / `draft` / `review_required`、再試行の二重計上なしを検証。終了時にこの検証で作成した架空データのみ削除。
- Chromeのローカル合成画面で35表の1フォーム表示、個別年月修正へ切替、エラー表示を確認。390px幅で横はみ出しなし。検証専用ルートは削除済みで本番に含めない。
