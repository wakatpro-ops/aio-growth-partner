# 発注・仕入先

店舗は「メニュー・仕入（店販）」の在庫タブから「発注・仕入先」を開きます。運営管理者が店舗ごとに契約上の仕入先アカウント発行上限を設定すると、店舗の管理者がその範囲内で仕入先を登録・招待できます。仕入先専用画面に課金や有料契約の導線はありません。

1. **店舗**：仕入先の事業者名とメールアドレスを登録し、招待メールを送ります。登録番号も確認できた場合は設定します。
2. **店舗**：数量・税抜単価・税率を確認し、発注の下書きを保存します。在庫の発注目安以下の商品から開くと、品名と単位が入ります。下書きは仕入先に見えず、「仕入先へ発注する」で共有します。
3. **仕入先**：案内メールから専用画面に入り、自社への注文を受注または辞退します。受けた注文を出荷・納品する際に連絡を記録します。
4. **店舗**：納品内容を確認し、実際の納品日を記録します。
5. **仕入先**：店舗が登録した発行者名・インボイス登録番号と取引内容を確認し、請求書番号を入力して発行します。両者が同じ取引画面で請求書を確認・ダウンロードできます。
6. **店舗**：実際の支払い後、支払済みとして記録します。

招待リンクは30分・1回限りで、次回は専用ページから再発行できます。店舗の発注管理は店舗管理者・法人オーナー・運営管理者のみ、仕入先は招待されたアカウントの取引のみです。削除済みの取引は通常一覧と分け、復元できます。進行中の取引がある仕入先は削除できません。完了後に仕入先を削除しても取引・請求は保持され、仕入先のログインだけが止まります。

請求書は、発行時の発行者・宛先・登録番号と明細・税額のスナップショットです。8%・10%それぞれの税抜額から税額を計算し、税率ごとに1円未満を切り捨てます。未払いの請求書は理由を添えて取り消し、別番号で再発行できます。取消前の内容は残り、HTMLでダウンロードできます。宛先は発注時の法人名を用います。登録番号の書式は検査しますが、国税庁への実在照会は行いません。

初版は一つの発注に対し一つの有効な請求書、整数数量、円建てです。分納・月締め合算請求・金額の差し替え・仕入先独自APIとの連携は未対応です。発注・検収で在庫数や会計を自動更新することはなく、支払済みの操作でも決済を実行しません。

## 検証と反映

- `npm run test:supplier-procurement`：ローカル PostgreSQL（`initdb`・`pg_ctl`・`psql`）に使い捨てのDBを作り、実マイグレーションで権限、招待枠、状態遷移、税計算、請求書と履歴の保持を検証します。
- `npm run build` 後の `npm run test:supplier-procurement:browser`：ローカルのブラウザでモバイル表示と未ログイン時のアクセス制御を検証します。既存のChromeを使うなら `AIOB_CHROMIUM_CHANNEL=chrome` を指定します。
- 隔離環境ではマイグレーションを先に適用し、テスト店舗にのみ招待枠を設定します。アプリの HTTPS URL を明示する `APP_BASE_URL`（または `NEXT_PUBLIC_APP_URL`）と、既存メール送信設定を利用します。架空の仕入先用メールで配信・再ログインから請求書受領まで確認してから本番の導入を判断します。
- ステージングに送信設定がない場合は、既存の送信設定を保持した Vercel Preview にステージングDBを接続し、`PROCUREMENT_PREVIEW_MAIL_TO` にテスト受信箱を指定できます。その場合、メールの行き先は同じ Preview に固定し、メール送信は仕入れ用の2種類と指定した1宛先だけに制限します。通常の Production にこの環境変数は設定しません。
- この実装だけで補助金の対象ツール登録や電子帳簿保存法への適合を保証しません。対象制度の申請には、契約・利用条件、証憑の検索・保存・出力要件、ITツール登録の確認を別途行ってください。
