# 売上・経理の会話型準備

Issue #182。月別推移と主要数値を上部に残し、指定された商品/支払内訳、操作カード、詳細集計を既定で閉じた「機能一覧」にまとめる。`#reports` のブックマークは自動展開する。

## 会話の流れ

- 店舗の売上有無・既存の未削除下書きを根拠に、一つの提案を表示。同順位だけ重み付き選択。「あとで」「別の提案」を保存。
- 見積/請求を選択 → 商品または自由入力 → 宛先または後で指定 → 数量/単価/税込税抜/税率 → 任意の説明 → 金額確認 → 下書き生成 → 既存編集画面。
- 登録商品/顧客は当該店舗の未削除データだけ。候補先頭100件、その他は直接入力または既存編集画面。まず単一商品/サービス、整数数量・円単価を扱う。複雑な内訳は既存編集画面で確認する。
- 取り込み、伝票、分析など書類下書き以外は、入力ファイル/月などを選べる既存画面へ。領収/入金を架空に生成しない。
- モバイルは既存の展開式下部AIドック。閲覧者は読み取り相談へフォールバック。

## 境界

金額は整数演算・円未満切り捨て。税込から税を分離/税抜へ加算。AIには金額・宛先個人情報を渡さず、備考のみ生成。`sales_conversation` で既存の使用量計測を利用。

会話は店舗×操作者で保存。CAS revision、生成lease、固定generation UUIDで競合と応答喪失時の重複を防ぐ。RPCが書類下書き+監査+完了状態を同一トランザクションで確定。商品/顧客の再検証、サーバーとDBで編集権限確認、RLS/service-role限定RPC。

作成状態は必ずdraft/unpaid/not_created。発行日時、PDF履歴、決済、送信、売上取引は作らない。正式連番を消費せず仮番号で保存、編集画面に明示。通常の書類一覧/編集/削除済み/復元を使い、関連履歴を保持する。

本番反映前に合成データの隔離プレビューで店舗/操作者/閲覧権限、CSRF、重複、税込税抜、選択後の変更、生成と編集画面、削除/復元、副作用なし、使用量を検証する。個人情報・認証情報を証跡に残さない。
