# Excel集計表の取り込み — Issue #166

## 変更の目的

一つのシートに日別売上・担当者別内訳・経費表が同居する帳票を、一つの一覧と誤解しない。元のセルを追跡できる整理候補を作り、人が確認するまで業務データへ反映しない。

## 読み取りと確認

- 通常の一覧は物理行番号を保持し、繰り返し見出し・小計を区別する。同名列を上書きせず、元列位置付きで選択する。
- 日別の件数・金額が交互に並ぶ横持ち帳票は日付・サービス・数量・金額へ展開する。
- 担当者別の内訳を重ねて足さない。総合計の式による参照関係が確認できない別表は、黙って採用せず確認を求める。
- 累計は売上明細に重ねて登録しない。日計・月計の保存値と明細を照合する。
- 経費は別表として整理する。用途を支払先と決めつけない。
- 年月の矛盾、存在しない日付、数式の結果欠落、合計不一致は表単位で停止する。確認チェックで異常を無視することはできない。問題のある表を対象外にするか、元ファイルを修正する。
- 数式の文字列と保存済み結果を読み取るだけで、マクロ・数式・外部リンクを実行しない。保存値が最新であることは保証できないため、必要ならExcel側で再計算して保存する。
- 非表示シートは自動反映せず、除外理由を表示する。

## データ保全

- 古い方式の未反映ファイルは「元ファイルを再解析」で読み直せる。以前の解析結果と元ファイルは削除済み履歴に保持する。反映開始済みファイルの再解析は禁止。
- 店舗・法人の認可、ファイルハッシュ照合、状態の楽観ロックを通す。売上・経費は再解析で変更しない。
- 取り込み確認・実行・売上再集計は1,000行上限に依存せずページングする。取得件数が合わないときは停止する。
- 日別サービス別の集計には、その粒度と元セルを記録する。過去集計から現在の在庫を自動で減らさない。
- 曖昧な調整額・値引き・振込額を日別売上へ勝手に配賦しない。

## 検証結果（2026-10-03）

- 上記の全ローカル検証と本番用ビルドを通過。PCと390px幅のChromeで表の展開、文言の折り返し、確認欄を確認した。
- `test:staging:unified-import` は既存stagingプロジェクトを名前・organization・refで照合し、新規の合成店舗・利用者・ファイルのみで実行する。秘密値はCLIからメモリ内でのみ利用する。
- 実DBでアップロード→確認前の実行拒否→確認→負数を含む保存・再集計、過去集計による在庫変動なし、1,205行の全件レビュー、再解析時の旧行保持、未所属ユーザーの操作拒否とRLSを確認した。合成レコード・アカウント・ファイルは後片付け済み。
- 競合するレビュー保存は1件だけ成功し、古い画面からの保存は行を書き換えない。表の除外を行単位の指定で迂回できない。
- 集計や完了状態の保存が失敗した場合は、取込済みの行を保持し、未完了の処理だけ再試行する。
- 元ファイル内の年月矛盾・不明な調整額は、確認なしに補正・反映しない。本番の業務データ反映は別の確認操作とする。
