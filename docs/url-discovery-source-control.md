# URL診断の検索・出典訂正・回復導線（#191）

## 目的

2026-10-08 の yoomi / Amour by mee の報告に対応。取得できないURLですぐ店舗名を聞かず、URLから検索する。検索で別店舗を混ぜることや、同じ質問を繰り返すことを防ぐ。

## 動作

- 403・ログイン要求などの取得失敗時も、公開URLそのもの／店舗ID／SNSハンドルの検索を先行。認証や取得拒否を迂回しない。
- URLから候補を採るには、同一掲載URLが検索ツールの出典に含まれ、店舗名と地域の証拠が一致することが必要。似た名前だけでは採用しない。
- ヒント入力後は店舗名と地域の両方を照合。飲食・美容の代表媒体も検索対象にするが、掲載の存在や検索順位・網羅性は保証しない。
- 参照URLごとに「ページ本文を取得」「検索で参照」を表示。メニュー・サービスの取得内容も表示する。簡易診断は写真を取り込む機能ではない。
- 「× 除外」は旧診断での申し込みを止め、新しい診断として全項目を再構成する。再診断では同じサイト全体を使わないことをUIで説明する。前のプロフィールをAIへ渡さず、除外サイトを使ったAI結果は採用しない。元の匿名診断は履歴として保持し、既存の店舗データは変更しない。
- 名前・地域の検索が不成立なら、同じ入力での再調査を無効化。補足した再調査／別URL／手入力で確認へ進む、を選べる。
- 手入力で進む場合は明示的なチェックを必要とし、`self_reported`・`user_provided` を記録。公開情報の確認成功や所有者の確認を意味しない。既存のメール確認・権限申告・運営承認は継続する。
- URL安全性検査、レート制限、最大2回のAI呼び出し、古い診断の拒否は維持する。

## 検証

- `node scripts/test-public-identity-recovery.mjs`: URL検索の先行、別地域の拒否、入力URLの検索証拠、出典除外、クエリに店舗IDを含むURL、手入力の出典区分、SSRF拒否、レート制限、回復UI契約。
- `npm run test:url-onboarding`, `npm run check:url-onboarding`, 型検査・対象lint・秘密情報チェック。
- 本番反映前に、既存の保護済みAI設定とステージングDBを使う隔離プレビューで検証する。申込・メール送信・店舗データ作成は行わない。

## 制約

出典除外時に検索ツールが除外ページを参照した場合、その結果は安全側で不採用にする。削除ボタンでURLだけを隠し、情報を残す実装にはしない。検索結果が少ないSNS店舗は自動特定できないことがあり、その場合は未確認の手入力情報として継続できる。

検索には Responses API の `web_search` と `filters.blocked_domains` を使用。既存の保護済みキーとモデルをそのまま使い、新規契約・追加キー発行は行わない。公式仕様: https://developers.openai.com/api/docs/guides/tools-web-search#domain-filtering
