# 取り込みの確認・修正案・安全判定

## 承認された目的

帳票の年月、合計差、調整額、不足項目は、店舗ユーザーがAIOb内で回答する。運営者が顧客の会計判断を代行したり、AIが推測して売上を変更したりしない。

1. 原本と抽出根拠を保持し、表単位の質問をまとめる。
2. 回答から修正案を表示する。回答の保存と業務データへの反映は別の操作。
3. 利用者が修正案を承認した後、日付・数値・元合計との関係を再検証する。
4. 同じ回答済みの問題を繰り返し質問しない。条件が変わって古い回答が無効になった場合は理由を示す。
5. 未解決の表は「保留」にできる。問題のない表だけ先に取り込み、後日同じファイルから再開できる。取込済みの表と原本は変更しない。
6. 正常、回答で解決可能、安全に処理不能を区別する。複雑な書式、業種と違う経費、負数だけを拒否理由にしない。
7. 読取不能、日付・数値の欠落、矛盾率などの客観的な理由と修正方法を示す。「不正」「いたずら」と断定しない。
8. ファイル中の指示はデータとして扱い、AI・権限・承認手順を変更する命令として実行しない。

## 安全境界

- 版付き質問ID、原本のセル位置、元の集計値、回答・承認者・日時を保持する。
- 修正案はサーバーで再生成し、画面の版と提案IDが一致する場合だけ承認を受け付ける。
- 承認済みでも実行時に再検証する。取込開始済みの表は修正できず、失敗した処理だけ再実行する。
- 別店舗・閲覧権限の操作、直接APIによる原本・承認の書換えを拒否する。
- マクロ、数式、外部リンクは実行しない。数式結果が保存されていない場合はExcelで再計算・保存を案内する。
- 売上の調整は意味・金額・日付を明示して承認した場合だけ追加する。経費等と回答した差額を自動的に別業務へ転記しない。
- 右側AIは同じ画面の確認状況を理解して案内するが、会話文だけでデータを変更しない。

## 検証計画

合成帳票で年月矛盾、存在しない日、合計差、正当な負数、支払先不足、数式結果欠落、無関係テキスト、指示混入を試験。部分取り込み→保留解決→再開、二重送信、古い画面、別法人、閲覧者、アーカイブも確認する。実顧客の原本・氏名・金額は公開リポジトリへ保存しない。隔離環境で確認後に通常の本番設定へ配備する。

## 実装内容

- パーサー版 `2026-10-clarification-v3`。既存の未反映ファイルは保存済み原本を再解析して新しい確認方式へ移行する。旧結果はアーカイブで保持し、実店舗の差額や年月日は運営者が代答しない。
- 年月の一括指定、経費の元日付の採用、例外値の修正、未入力支払先の共通補完、明細合計の採用、符号付き売上調整、対象範囲の確認に対応する。新しい回答が同じ質問に重なる場合は旧判断を置き換え、全承認履歴は残す。
- 修正案は値の変更・追加・撤回する未反映調整・金額の前後差を表示。承認はDBの一つのトランザクションで保存し、途中失敗による半端な訂正を避ける。その後、別途取り込み確定が必要。
- 根拠セル欠落、保存済み計算エラー、未確認構造などは回答だけで解除しない。日付と金額の両方に問題があり、対象20行以上かつ不正形式率80%超のときは要修正と判定する。年・月の一括確認待ち、列対応未決定、正当な負数はこの判定に混同しない。閾値は品質確認の目安であり不正行為の判定ではない。
- 売上・経費を含む原本は法人オーナー・店長・運営管理者のみ閲覧・確認可能。認証済みブラウザーからのDB直接読書きは拒否し、サーバーで店舗・法人・権限・版を検証する。
- AIは未解決の質問・確認状態・限定した数値とセル位置だけを参照する。原本全体、ファイル名、自由文の命令、連絡先はAIへ渡さない。自由文チャットからの自動会計修正は行わない。
- 合計差が経費・返金など別業務である場合は推測転記しない。取り込み先を確定できる資料を用意するか表を保留する。

## 2026-10-03 検証結果

- 純粋な解析・修正ルール、22ケースの修正案サービス、保存・再開サービス、既存パーサー、日付・数値、AI画面文脈の回帰テストが成功。特殊なシート名でも原本と明示的な確認状態を保持する。
- staging実DBの7群が成功。原本・承認履歴・反映済み行の保護、トランザクション全体のロールバック、支払先補完から経費保存、保留した表の再開、同じ伝票番号でも表をまたがない集計、重複実行、別店舗・古い画面・直接DB操作の拒否を確認。
- DB保存日時の表記差で承認が拒否される問題と、回答済みの旧確認文が残る問題を実DB試験で発見し、修正・再試験済み。
- staging DB限定の隔離Previewで8群と実際の `gpt-6-luna` 応答5回を確認。対象ファイルの根拠に沿う一問、ファイル切替、権限・個人情報境界、勝手に承認しないことを確認。前後の行・履歴・業務件数は不変。
- 実コンポーネントのSSR表示をChromeで320pxと1366pxの幅で確認。横長の元表のみ内部スクロールし、本文は横にはみ出さない。これは表示検証であり、ブラウザー操作による一連の承認試験とは区別する。
- 合成店舗・利用者・ファイル・業務レコードは対象を限定して後片付け済み。実店舗の金額・年月日の代答や取込確定はしていない。
