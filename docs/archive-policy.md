# アーカイブ・削除方針

## 原則

AIO boostでは、ユーザーが作成できる主要な業務データを物理削除しない。通常画面から整理するときは `archived_at` と `archived_by` を記録し、関連データを保ったまま非表示にする。アーカイブ済みデータは店舗内の「アーカイブ管理」から復元できる。

アーカイブ済みデータは、通常一覧、入力時の選択肢、AIへの入力、件数表示、会計出力、外部送信対象から除外する。

## 対象

| 対象 | 整理方法 | 復元 | 備考 |
| --- | --- | --- | --- |
| 店舗 | アーカイブ | 店舗一覧から可能 | 組織オーナーまたは運営管理者のみ |
| 組織 | アーカイブ | 運営管理から可能 | 利用中店舗を先にアーカイブする |
| ユーザー・所属 | アーカイブ | 運営管理から可能 | Supabase Authの本人アカウントは削除しない |
| 申込 | アーカイブ | 運営管理から可能 | 営業履歴、発行済み店舗・ユーザーを保持 |
| 商品・サービス | アーカイブ | 店舗のアーカイブ管理から可能 | 過去明細との関係を保持 |
| 顧客 | アーカイブ | 店舗のアーカイブ管理から可能 | 過去の見積・請求との関係を保持 |
| 見積・請求 | アーカイブ | 店舗のアーカイブ管理から可能 | PDF・入金・監査履歴を保持 |
| 受注 | アーカイブ | 店舗のアーカイブ管理から可能 | 状態変更履歴を保持 |
| 売上取込履歴 | アーカイブ | 店舗のアーカイブ管理から可能 | 取込済み売上は会計・分析の証跡として保持 |
| AIレポート・改善提案 | アーカイブ | 店舗のアーカイブ管理から可能 | 再生成時も旧結果を物理削除しない |
| 集客下書き・アクション | アーカイブ | 店舗のアーカイブ管理から可能 | 公開・送信・承認履歴を保持 |
| 経費レシート | アーカイブ | 店舗のアーカイブ管理から可能 | 元ファイルとfreee連携履歴を保持 |

## アーカイブしない証跡

次の情報は履歴そのものなので削除ボタンを設けない。

- 入金記録（誤りは取消状態で訂正）
- PDF発行・再発行履歴
- 操作監査ログ、AI利用ログ
- Stripe、Google、freeeなどの外部連携ログ
- Webhook受信・外部送信結果

## 実装チェック

新しい永続データを作成できる画面を追加するときは、`AGENTS.md` のライフサイクル完全性チェックを満たす。アーカイブを実装しない場合は、証跡性などの理由をこの文書へ明記する。
