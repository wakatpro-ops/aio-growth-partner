# 公開情報からの商品登録を確認ベースにする

## 原因と修正

従来は `extracted_profile.services`（ランチ・個室利用などの提供分野）を、そのまま販売商品へ変換し、取得していない単価を0円で補完していた。モデル設定ではなく、抽出結果の型と後続の既定値の問題。

- 店舗の特徴 `services` と商品候補 `menu_candidates` を分離。候補には名称、円価格またはnull、税込／税抜／不明、出典URL、短い根拠、直接取得／検索由来の区別を残す。
- 直接取得した構造化データと名称・価格が対になる表から抽出。外貨、価格帯、平均予算、矛盾する価格を単価に変換しない。
- 同じ検索リクエストでも個別商品候補を収集するが、検証済みツール出典に限定し、未確認として表示する。検索で見つけた公式ページを最大1サイトだけ追加取得する。SSRF・DNS・リダイレクト・403・容量・時間制限は既存の安全な取得処理を再利用し、除外ドメインや別店舗の情報は採用しない。
- 初期設定は候補を未選択で表示。名称・価格・税区分の個別確認が必須。無料は追加確認が必要。価格不明のまま利用開始する場合は商品登録を保留できる。旧下書きの自動選択も復元しない。
- 確定時の同意と価格チェックはサーバーにも実装。登録商品には確認フラグと元の出典・根拠を保存。店舗の特徴は商品選択によって消さない。
- 旧初期設定由来の未確認0円商品は、DBを一括書換・削除せず、画面上「要確認／価格未設定」にする。店長以上が編集画面で明示確認してから利用できる。手動登録の無料商品や確認済み無料商品は維持する。
- 未確認商品は新しいSNS・書類の選択、AIの商品コンテキスト、売上取込の自動紐付けから除外する。既存の売上・発行済み書類は変更しない。AIには確認待ち件数を伝える。

モデル・APIキー・モデル選択の環境変数は変更しない。写真の権利や不足価格を推測で補わず、全サイトの全メニュー取得は保証しない。旧データから実際の商品名・価格を復元したとは扱わない。

## 検証

- `npm run test:onboarding-menu`：抽出・価格・税・出典・旧データ・無料・確認拒否・初期設定重複・権限。
- `node --experimental-strip-types scripts/test-initial-setup-duplicates.mjs --staging`：指定済みステージングDBの架空データだけで実際の登録処理を検証し、後片付けする。本番では実行しない。
- `node --experimental-strip-types scripts/render-onboarding-menu.mjs`：実コンポーネントを架空データで描画。旧下書きの未選択、価格未設定、正規商品と無料の区別を確認。生成物はローカル限定。
- 型検査、lint、build、全unit、URL取込、統合取込、AIコンテキスト、アーカイブ、秘密情報チェック。
- ブラウザーでPC・320px・390pxを確認。外部公開投稿、メール、請求書発行は行わない。

既存テストのローカル変数 `module` を `loaded` に置き換え、Next ESLintの既存違反を解消。業務ロジックは変更していない。
