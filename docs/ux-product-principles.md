# AIO boost 店舗管理者UX原則

## 売る体験

AIO boostの中心価値は、店舗運営機能の数ではない。店舗が「地域や目的を含む質問でAIにおすすめされるために、何を改善すべきか」を理解し、改善し、外部へ反映する体験を提供する。

初回ログインの成功条件は、全設定の完了ではなく、利用者が想定質問と最優先の改善1件を理解し、その改善に着手すること。

## URLから始める導入体験

申し込み前の最初の入力は、店舗を確認できる公開URL 1件だけにする。公式サイトがない場合は、予約サイト、ポータルサイト、Googleマップなど、店舗情報を確認できるURLを受け付ける。

URL送信後は、連絡先や多数の設定項目を先に求めず、取得できた公開情報から次を提示する。

1. AIが読み取った店舗名、業態、地域、メニュー、特徴、強み
2. お客様がAIへ尋ねそうな地域・目的を含む質問候補
3. 現在の `AIおすすめ準備度` と、その算定根拠
4. 最初に改善すると効果を理解しやすい項目
5. 読み取れず、管理画面の初期設定に必要な確認だけ

利用者が読み取り結果を確認した後に、結果の保存・導入相談・契約案内に必要な氏名、メール、電話番号を求める。質問は読み取れなかった高重要度項目を優先し、一度に3件程度までとする。すでに公開情報から取得できた項目を再入力させない。

AIが読み取った情報は確定情報として扱わず、`AIの読み取り結果` と表示して利用者または運営者が修正できるようにする。取得失敗時も大量の従来フォームへ戻さず、URLの確認、別URLの追加、最小限の手入力という順で回復させる。

アカウント発行時は、確認済みの読み取り結果を店舗プロフィール、業態別表示、想定質問、初回AIO改善、推奨機能へ引き継ぐ。初回ログインで同じ情報を入力し直させない。

## 情報の優先順位

店舗トップでは次の順で表示する。

1. AIO改善・集客
2. 売上管理
3. 今日やること

主要入口は `店舗トップ / AIO改善 / 集客 / 売上 / 設定` の5つに限定する。見積書・請求書・領収に使う入金記録は「売上」の中へまとめる。

## 表示と操作

- 主ボタンは塗り、枠、hover、動詞付きラベルで操作だと分かるようにする。
- 静的カードは薄い背景と細い枠を使い、ボタンのhover表現を持たせない。
- 回収可能な削除は、画面では `削除 / 削除済み / 元に戻す` と書く。内部実装はアーカイブを維持する。
- 保存中、成功、失敗を必ず伝える。成功後は一覧または明示した次画面へ遷移する。
- 新規・編集・詳細には戻る導線を出す。
- 税は `税込（内税） / 税抜（外税）` を選べるようにし、8%は該当業態でだけ表示する。

## AIO表示の誠実さ

`AIおすすめ準備度` は、名称・地域・提供内容・信頼できる公式URL・外部反映など、AIが参照しやすい情報の準備度を示す。特定のAIによる推薦や順位を保証しない。

準備度と、Google・Web・SNSへの外部反映状況は必ず別に表示する。

## レビュー項目

- PC幅とタブレット幅で、最初に押すボタンが1つに見えるか
- 四角い要素が、操作か情報かを迷わないか
- 保存後に完了を認識でき、次の位置が分かるか
- 一覧へ戻れるか
- 削除後にどこへ移り、どう戻すか分かるか
- 飲食店以外で軽減税率8%が画面を占領していないか
- 初回画面に請求・税・CSVなどの周辺設定が割り込んでいないか
